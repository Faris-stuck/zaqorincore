## F-027 — Cloudflare Logpush NDJSON depth DoS

`json.loads` is unbounded in nesting depth. A 64 KiB line of deeply-nested
JSON trips the interpreter recursion limit and 500s the batch. The
fix extracts a `DepthLimitedDecoder` into a reusable
`zaqorincore_server.utils.depth_json` module and uses it for the
NDJSON line parse in `ingest_cloudflare.py`.

```python
from ...utils.depth_json import safe_loads
record = safe_loads(line.decode("utf-8", errors="replace"))
```

## F-028 — Webhook body / message depth DoS (F-027 sibling)

`ingest_webhook.py` line 304 (per-record `message`) and line 497
(whole body) used raw `json.loads`. Both are now routed through
`safe_loads`. The 1 MiB body cap already bounded total bytes, but
the depth cap is the layer that catches `[[[...]]]]` payloads
within the byte budget.

## F-029 — WS HELLO frame uncapped (F-009 residual)

`stream.py` line 103 read the HELLO frame with no application-level
byte cap. The F-009 fix only capped subsequent frames, *after*
`receive_text()` returned — so a multi-MiB first frame was already
buffered. The fix adds a tight 64 KiB HELLO cap and uses
`safe_loads` for both the HELLO and per-event-frame parse.

```python
MAX_HELLO_BYTES = 64 * 1024
first_raw = await ws.receive_text()
if len(first_raw) > MAX_HELLO_BYTES:
    await ws.close(code=1009)  # message too big
    return
first = safe_loads(first_raw)
```
