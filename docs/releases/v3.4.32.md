## F-031 — Path traversal in `rules_studio._resolve_path`

The internal helper builds the YAML path as
`base / f"{rule_id}.yml"` and is called from:

| Endpoint | Helper | Fix |
|----------|--------|-----|
| GET `/api/v1/rules/{rule_id}` | `_read_rule_detail` | `_validate_rule_id` |
| PUT `/api/v1/rules/{rule_id}` | `update_rule` | `_validate_rule_id` |
| DELETE `/api/v1/rules/{rule_id}` | `delete_rule` | `_validate_rule_id` |
| POST `/api/v1/rules/{rule_id}/test` | `_read_rule_detail` | `_validate_rule_id` |
| POST `/api/v1/rules` | `_sanitize_rule_id` (stricter) | already present |

```python
_RULE_ID_PATTERN = re.compile(r"^[A-Za-z0-9_.\-]{1,64}$")

def _validate_rule_id(rule_id: str) -> str:
    if not isinstance(rule_id, str) or not _RULE_ID_PATTERN.match(rule_id):
        raise HTTPException(
            status_code=400,
            detail=(
                "rule_id must match [A-Za-z0-9_.-]{1,64}; "
                "path traversal characters are not allowed"
            ),
        )
    return rule_id
```

The POST handler keeps its stricter `_sanitize_rule_id` (snake-
case only, length [3, 64]) because that path is body-supplied
and naming convention matters for on-disk hygiene. The
`_validate_rule_id` helper covers the URL-supplied paths.
