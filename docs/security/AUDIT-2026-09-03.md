## What was NOT found (good)

* No SQL injection patterns
* No pickle / unsafe-yaml / marshal
* No `shell=True` / `os.system`
* No `hashlib.md5`/`sha1` for security purposes
* No `random.choice` / `random.randint` in crypto paths
* No `==` on tokens/hashes (all use `hmac.compare_digest`)
* No `dangerouslySetInnerHTML` in WebUI
* No `cors` middleware with permissive `allow_origins`
* No hardcoded test creds in production code paths
* No known-bad minimum versions on direct deps

## Top 3 issues (one-line answer)

1. **`/api/v1/stats` + `/api/v1/version` leak version, git SHA, pid, agent count to unauthenticated callers** (F-006)
2. **No lockfile — every dep is a `>=` range, supply-chain drift on every install** (F-011)
3. **`audit` log is in-memory only — lost on process restart, bounded to 1024 entries** (F-008)

## Round 8 (cycle 72) — 2026-09-03

Narrow-scope re-hunt of the post-F-017 fix surface:
`server/src/zaqorincore_server/self_defense/csp_violation_reporter.py`
at commit `c83ae1c` (v3.4.13).

Scope: 1 file (140 LOC). READ-only audit — no code modified.

Vectors reviewed:
- Race conditions in the per-src_ip throttle (F-017 used a dict; is
  the dict access thread-safe?).
- Off-by-one errors in the timestamp comparison
  (`now - first_seen` vs `expiry`).
- Memory growth: the per-src_ip dict has no eviction policy
  (bloat potential).
- Key length limits: what if `document_uri`/src_ip is unbounded?
- The `/v1/csp-report` endpoint: is it authenticated? If not, is the
  throttle sufficient to prevent abuse?
- Residual issues from the original F-017 finding that the fix did
  not address (per-endpoint body cap, event-stream amplification).

| ID | Severity | Title | Status |
|---|---|---|---|
| [F-023](findings/F-023-csp-reporter-throttle-eviction.md) | Medium | CSP reporter throttle: race in `_throttle_allowed`, no eviction in `_recent`, no per-endpoint body cap, throttled traffic evicts `_STREAM` audit | **Closed in v3.4.14** — threading.Lock + _evict_stale + 16 KiB cap + no emit on throttle + 7 regression tests |

### Round 8 details

**Found four residual issues on the F-017 fix surface:**

1. **`_throttle_allowed` is not thread-safe.** The dict + deque
   mutation sequence (setdefault → popleft → len → append) runs in
   FastAPI's async threadpool without a lock. The GIL protects
   individual ops but not the composite; concurrent requests from
   the same src_ip can briefly exceed the 10/min budget.

2. **`_recent` has no eviction.** Stale src_ip keys are never
   removed from the outer dict; only the per-key deque ages out.
   An attacker rotating src_ips (IPv6 spoofing, residential proxies)
   can grow the dict until the process is OOM-killed.

3. **No per-endpoint body size limit.** F-017's original finding
   called for a 64 KiB cap; the F-017 fix only changed the throttle
   key. 1 MiB × 10/min/IP of unauthenticated ingress is still
   possible.

4. **Throttled requests emit events, evicting legitimate audit.**
   Lines 130–134 of `csp_violation_reporter.py` call `emit(event)`
   with `status=429` on every rate-limited request. `_STREAM` in
   `self_defense/__init__.py` is bounded to 4096 entries
   (`deque(maxlen=4096)`); sustained throttling pushes legitimate
   events out, amplifying F-008 (in-memory audit log only).

**Clean:** off-by-one in timestamp comparison (the
`bucket[0] < cutoff` check is correct inclusive sliding-window
semantics), the explicit no-auth design (intentional and
documented; CSRF not applicable for an unauthenticated sink), and
the `src_ip` derivation chain (proxy opt-in via
`ZAQORIN_SRC_IP_HEADER` is well-documented; XFF left-most token
parsing handles chained headers correctly).

**Related but out of scope:**
- F-008 (in-memory audit log, 4096 maxlen) — same root cause as
  Issue 4, but F-008 is the audit-log fix, not the CSP-reporter
  fix. F-023 cites F-008 explicitly and does not duplicate it.

| ID | Severity | Title | Status |
|---|---|---|---|
| [F-024](findings/F-024-csp-reporter-chunked-bypass.md) | Medium | CSP reporter 16 KiB cap is a Content-Length-only hint; bypassable via `Transfer-Encoding: chunked` | **Closed in v3.4.16** — reject TE: chunked with 411 + 1 regression test |

### Round 9 details

**F-023 fix-surface check results:**

1. **Lock scope (global vs per-IP).** `_throttle_lock` is module-level
   (line 89) and acquired inside `_throttle_allowed` (line 115). It
   guards both the `_recent` dict and every per-IP deque atomically.
   Global scope is correct here — atomicity across keys matters.
   **Clean.**

2. **`_evict_stale()` correctness.** Traced with mixed IPs:
   - IP A: deque=[0.0, 30.0], latest=30.0 → not stale at t=70
     (cutoff=10.0).
   - IP B: deque=[10.0], latest=10.0 → not stale at t=70
     (boundary: `bucket[-1] < cutoff` is strict less-than, so 10.0
     stays).
   - IP B: latest=10.0 < cutoff=11.0 at t=71 → evicted.
   Logic correctly removes entries whose most recent timestamp is
   strictly past the window. **Clean.**

3. **`_throttle_lock` acquisition point.** Acquired only inside
   `_throttle_allowed` (the sole mutator). `receive_csp_report`
   delegates via the helper. **Clean.**

4. **SSRF risk in CSP payload.** `blocked_uri` is parsed by
   `event_normalizer.from_csp_report` (line 193) and stored on the
   event, but **never** used to trigger an outbound HTTP request.
   The only outbound from this module is `emit(event)` writing to the
   in-process `_STREAM`. **Clean** (no SSRF surface).

5. **`_resolve_src_ip` against XFF injection.** Starlette's
   `request.headers.get()` returns the parsed header value (CRLF
   rejected at the HTTP parser; one logical value per header). The
   `split(",", 1)[0].strip()` operates on a sanitized string.
   An attacker injecting `"1.2.3.4, 5.6.7.8\r\nX-Evil: 1"` would get
   the literal string back from Starlette; the first token
   `1.2.3.4` becomes the src_ip. No header smuggling possible.
   Minor defense-in-depth note: no explicit length cap on XFF value
   before dict-keying, but Starlette/Uvicorn cap total header size.
   Not enough for a separate finding. **Clean.**

6. **16 KiB cap bypassable via `Transfer-Encoding: chunked`.** **YES.**
   Lines 169-180 of `csp_violation_reporter.py` check only the
   `Content-Length` header. When chunked encoding is used,
   `request.headers.get("content-length")` returns `None`, the check
   is skipped, and FastAPI reads the full body for JSON parsing.
   No global body-size middleware exists in the app (verified: only
   `SecurityHeadersMiddleware`, `RateLimitMiddleware`,
   `RequestIDMiddleware`, `ErrorEnvelopeMiddleware`, optional CORS).
   The F-023 Issue 3 fix is incomplete — the 16 KiB cap is restored
   to bypass via the same shape F-023 was trying to close. Filed
   **F-024** (Medium, residual of F-023 Issue 3, CWE-400 + CWE-444).

**Clean:** five of six vectors. Only the Content-Length-only cap was
found incomplete.

### The F-025 finding (header-name coverage gap)

The F-024 fix at lines 179-181 reads:

```python
te = request.headers.get("transfer-encoding", "").lower()
if "chunked" in te:
    return FastAPIRawResponse(status_code=411, content=b"")
```

This checks only the canonical `Transfer-Encoding` header name.
Two adjacent header vectors bypass it and restore the original
F-024 amplification attack:

1. **Legacy `TE:` singular form (RFC 2068 / RFC 7230 §3.3.1)** —
   `TE: chunked` is the deprecated singular header form. Starlette's
   `Headers.get("transfer-encoding")` does NOT match `te`, so
   `"chunked"` is never seen. The body is read as a plain stream
   with no cap enforced (because Content-Length is also absent).

2. **Vendor prefix `X-Transfer-Encoding:`** — `X-Transfer-Encoding:
   chunked` is an unrelated header to h11/Starlette. h11 does not
   strip or normalize it; Starlette's `request.headers.get(
   "transfer-encoding")` returns `None`. Same bypass: body read
   as plain stream, no cap.

**Reproduction** (verified):
```
POST /test/ HTTP/1.1
TE: chunked
...1 MiB body streamed via generator...
→ 422 (JSON parse fail), BUT 1 048 576 bytes were read into memory
```
Same result with `X-Transfer-Encoding: chunked`. The 16 KiB cap did
not trigger; F-024's defense was bypassed via a different header
name that means the same thing.

**Why h11 does not help**: h11 does not trigger chunked body
decoding for `TE:` or `X-Transfer-Encoding:` — only the canonical
`Transfer-Encoding:` header. So the body is delivered to the
application as raw bytes, and our check (which only inspects
`transfer-encoding`) never sees the chunked framing claim.

**Recommended fix** (3-line expansion, additive, drop-in):
```python
te = (
    request.headers.get("transfer-encoding", "")
    or request.headers.get("te", "")
    or request.headers.get("x-transfer-encoding", "")
).lower()
if "chunked" in te:
    return FastAPIRawResponse(status_code=411, content=b"")
```
A more robust fix combines this header-name expansion with the
streaming byte counter from F-024's recommendation, so the cap is
enforced regardless of header name coverage.

7. **Error messages: leak rule contents / paths / stack traces** —

   error string echoes back a caret-marked snippet of the offending
   rule lines. `load_rules_from_dir` (line 429) catches the re-raise

   operator-controlled directories, not untrusted input), but the
   brief explicitly asked. Recommended fix in F-026 §"Recommended
   fix": split the PyYAML error on the snippet delimiter and keep
   only the structural prefix. One-line change.

8. **Compile cache poisoning** — **CLEAN (no cache).** `load_rules_from_dir`
   rebuilds the list on every call (line 420). No module-level cache.
   Compile is deterministic (same YAML → same `CompiledSigmaRule`),
   so caching would be safe but is not implemented. No cache, no
   poisoning surface.

9. **Pattern 4 grammar: constrained to 4 documented patterns?** — **CLEAN.**
   The three `re.fullmatch` patterns on lines 223, 233–234, 252–254
   enforce exactly four shapes:
   - `selection` (literal compare, line 219)
   - `selection and not X` (line 223)
   - `selection and (X or Y [or Z ...])` (line 233–234, single OR

     group, single NOT, no nesting)
   Anything else returns False (line 274) — fail-closed, no
   fail-open. The regexes are anchored, non-greedy, no backtracking.
   Pattern 4 grammar is strictly constrained.
