## What was NOT found (good)

* No SQL injection patterns
* No pickle / unsafe-yaml / marshal
* No `shell=True` / `os.system`
* No `hashlib.md5`/`sha1` for security purposes
* No `random.choice` / `random.randint` in crypto paths
* No `==` on tokens/hashes (all use `hmac.compare_digest`)
* No `dangerouslySetInnerHTML` in WebUI
* No `cors` middleware with permissive `allow_origins`
* No hardcoded test creds in production code paths
* No known-bad minimum versions on direct deps

## Top 3 issues (one-line answer)

1. **`/api/v1/stats` + `/api/v1/version` leak version, git SHA, pid, agent count to unauthenticated callers** (F-006)
2. **No lockfile — every dep is a `>=` range, supply-chain drift on every install** (F-011)
3. **`audit` log is in-memory only — lost on process restart, bounded to 1024 entries** (F-008)

| ID | Severity | Title | Status |
|---|---|---|---|
| [F-021](findings/F-021-install-warnings-prefix-overlap.md) | Low | F-019 redaction logic bypassed by DNS-name prefixes that overlap RFC1918 octets (`10.`, `100.`, …, `1720.`, …) | **Closed in v3.4.10** — `ipaddress.ip_address()` parse + 2 regression tests |

### Round 6 details

**Found:** the substring-prefix check at line 713 of
`agents_provision.py` (`host.startswith(("zaqorin-", "10.", "192.168.", "172."))`)
treats **DNS names** whose first label happens to start with `10.`,
`100.`, `101.`, …, `109.` (and `1720.`–`1729.`) as "internal", so
the F-019 redaction branch is skipped for those public DNS names and
the literal hostname is echoed back into the response. The original
F-019 test (`test_install_command_warnings_redact_public_dns`) uses
a hostname starting with `v`, so the overlap case was not covered.
**Clean:** auth token entropy (`secrets.token_hex(32)`, 256 bits),
artifact URL (not user-controlled, hardcoded template), all
user-supplied values flow through `_safe_host` / `_safe_user` /
`_safe_key_id` / the `agent_id` blocklist, heredoc delimiters use
single-quoted form (no shell expansion of body), PowerShell
here-string `@'…'@` (no PowerShell expansion), TOML escaping in
`render_agent_toml` covers `\` / `"` / all control chars, regexes
are simple anchored character classes (no backtracking). Phase 2 of
cycle 67 will close F-021 (helper + regression test).

## Round 8 (cycle 72) — 2026-09-03

Narrow-scope re-hunt of the post-F-017 fix surface:
`server/src/zaqorincore_server/self_defense/csp_violation_reporter.py`
at commit `c83ae1c` (v3.4.13).

Scope: 1 file (140 LOC). READ-only audit — no code modified.

Vectors reviewed:
- Race conditions in the per-src_ip throttle (F-017 used a dict; is
  the dict access thread-safe?).
- Off-by-one errors in the timestamp comparison
  (`now - first_seen` vs `expiry`).
- Memory growth: the per-src_ip dict has no eviction policy
  (bloat potential).
- Key length limits: what if `document_uri`/src_ip is unbounded?
- The `/v1/csp-report` endpoint: is it authenticated? If not, is the
  throttle sufficient to prevent abuse?
- Residual issues from the original F-017 finding that the fix did
  not address (per-endpoint body cap, event-stream amplification).

| ID | Severity | Title | Status |
|---|---|---|---|
| [F-023](findings/F-023-csp-reporter-throttle-eviction.md) | Medium | CSP reporter throttle: race in `_throttle_allowed`, no eviction in `_recent`, no per-endpoint body cap, throttled traffic evicts `_STREAM` audit | **Closed in v3.4.14** — threading.Lock + _evict_stale + 16 KiB cap + no emit on throttle + 7 regression tests |

### Round 8 details

**Found four residual issues on the F-017 fix surface:**

1. **`_throttle_allowed` is not thread-safe.** The dict + deque
   mutation sequence (setdefault → popleft → len → append) runs in
   FastAPI's async threadpool without a lock. The GIL protects
   individual ops but not the composite; concurrent requests from
   the same src_ip can briefly exceed the 10/min budget.

2. **`_recent` has no eviction.** Stale src_ip keys are never
   removed from the outer dict; only the per-key deque ages out.
   An attacker rotating src_ips (IPv6 spoofing, residential proxies)
   can grow the dict until the process is OOM-killed.

3. **No per-endpoint body size limit.** F-017's original finding
   called for a 64 KiB cap; the F-017 fix only changed the throttle
   key. 1 MiB × 10/min/IP of unauthenticated ingress is still
   possible.

4. **Throttled requests emit events, evicting legitimate audit.**
   Lines 130–134 of `csp_violation_reporter.py` call `emit(event)`
   with `status=429` on every rate-limited request. `_STREAM` in
   `self_defense/__init__.py` is bounded to 4096 entries
   (`deque(maxlen=4096)`); sustained throttling pushes legitimate
   events out, amplifying F-008 (in-memory audit log only).

**Clean:** off-by-one in timestamp comparison (the
`bucket[0] < cutoff` check is correct inclusive sliding-window
semantics), the explicit no-auth design (intentional and
documented; CSRF not applicable for an unauthenticated sink), and
the `src_ip` derivation chain (proxy opt-in via
`ZAQORIN_SRC_IP_HEADER` is well-documented; XFF left-most token
parsing handles chained headers correctly).

**Related but out of scope:**
- F-008 (in-memory audit log, 4096 maxlen) — same root cause as
  Issue 4, but F-008 is the audit-log fix, not the CSP-reporter
  fix. F-023 cites F-008 explicitly and does not duplicate it.
